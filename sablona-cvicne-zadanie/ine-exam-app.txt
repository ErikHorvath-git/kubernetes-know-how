═══════════════════════════════════════════════════════════════════
INE-EXAM-APP — ako premenovať image z `exam-app:latest`
                  na lubovolny nazov (napr. `<meno>-app:latest`)
═══════════════════════════════════════════════════════════════════

V šablóne 1 (1 deployment) je IBA JEDEN image — `exam-app:latest`.
Stačí na 2 miesta:
  1) zmeniť tag pri `docker build` a `minikube image load`
  2) zmeniť `image:` v k8s deployment-e (musí byť IDENTICKÝ string)

PRÍKLAD — premenovanie `exam-app` → `horvath-app`
─────────────────────────────────────────────────

Build + load (krok 5 v README.md / krok 4 v postup.txt):

    docker build -t horvath-app:latest -f Dockerfile .
    minikube image load horvath-app:latest

A v deployment-e zmeň `image:` tak, aby sa STRING zhodoval s tým, čo si
nahral do Minikube.

═══════════════════════════════════════
ZOZNAM SÚBOROV, KDE TO TREBA PREPÍSAŤ
═══════════════════════════════════════

(môžeš použiť jeden sed, ktorý ti premaže všetko naraz — viď úplne dole)

─── k8s manifesty (POVINNÉ — bez toho pod nebude vedieť, aký image bežať) ───

  k8s/deployment.yaml
      riadok ~52:   image: exam-app:latest      →  image: horvath-app:latest

  k8s/deployment-upload-init.yaml         (len ak používaš A+C COMBO)
      riadok ~46:   image: exam-app:latest      →  image: horvath-app:latest

  POZOR: `imagePullPolicy: IfNotPresent` NECHAJ — bez toho by k8s skúšal
         image stiahnuť z Docker Hubu (a tam tvoj custom image nie je).

─── Dokumentačné/príkazové súbory (VOLITEĽNÉ — len aby ti sedeli návody) ───

  README.md
      sekcia "5. Build image-u + load do Minikube"
      sekcia "9. Upratanie"                  (`docker rmi exam-app:latest`)
      tabuľka "Najčastejšie chyby"           (`minikube image load exam-app:latest`)

  README-template.md
      sekcia "Postup nasadenia" — kroky 1.

  postup.txt
      sekcia "4. BUILD IMAGE + LOAD DO MINIKUBE"
      sekcia "NAJČASTEJŠIE CHYBY" — riadok pri `ImagePullBackOff`

  Dockerfile — NETREBA prepisovať. Dockerfile nedefinuje názov image-u,
               názov sa nastavuje až flagom `-t` pri `docker build`.

═══════════════════════════════════════
RÝCHLA HROMADNÁ ZMENA (sed)
═══════════════════════════════════════

Z `~/exam` (alebo kde máš naskopírované súbory):

    # nahraď MENO svojím (napr. horvath, jano, ...)
    MENO=horvath

    sed -i "s/exam-app:latest/${MENO}-app:latest/g" k8s/*.yaml
    sed -i "s/exam-app:latest/${MENO}-app:latest/g" README.md postup.txt 2>/dev/null

A potom build s tým istým názvom:

    docker build -t ${MENO}-app:latest -f Dockerfile .
    minikube image load ${MENO}-app:latest

═══════════════════════════════════════
KONTROLA, ŽE TO SEDÍ
═══════════════════════════════════════

  # 1. image existuje v minikube
  minikube image ls | grep ${MENO}-app

  # 2. žiadny YAML už neodkazuje na starý názov
  grep -r "exam-app" k8s/ || echo "OK — nikde sa už nevyskytuje"

  # 3. apply a pozri status
  kubectl apply -f k8s/
  kubectl -n exam-meno get pods
  # Status musí byť Running. Ak je ImagePullBackOff:
  #   → buď si zabudol `minikube image load <nazov>`
  #   → alebo sa `image:` v deployment.yaml NEZHODUJE s tým, čo si loadol
  #     (skontroluj presne pomocou: kubectl -n exam-meno describe pod ...)

═══════════════════════════════════════
NA ČO SI DAŤ POZOR
═══════════════════════════════════════

  • Tag MUSÍ byť identický string (vrátane `:latest`). `horvath-app`
    a `horvath-app:latest` Kubernetes považuje za to isté (default tag
    je `latest`), ale `horvath-APP` a `horvath-app` NIE — názvy
    image-ov sú case-sensitive a Docker povolí len malé písmená.

  • Nepoužívaj medzery ani špeciálne znaky. Bezpečné: `[a-z0-9-]`.

  • Ak meníš aj namespace (`exam-test1` → `exam-meno`), rob to OSOBITNE
    od premenovania image-u (sú to dve nezávislé úpravy). Viď
    `renameNamespace.txt`.

  • `imagePullPolicy: IfNotPresent` je už v deployment-e nastavený —
    NEMEŇ ho na `Always`, lebo by k8s odignoroval lokálny image
    a skúsil ťahať z Docker Hubu.
