═══════════════════════════════════════════════════════════════════
POSTUP — krok po kroku ako to spraviť pri obhajobe
═══════════════════════════════════════════════════════════════════

═══════════════════════════════════════
1. PRÍPRAVA PRACOVNÉHO ADRESÁRA
═══════════════════════════════════════

mkdir -p ~/exam/{src,k8s}
cd ~/exam
cp ~/poznamky/Dockerfile ./
cp ~/poznamky/k8s/*.yaml ./k8s/

═══════════════════════════════════════
2. VÝBER VARIANTU (jeden z A-D)
═══════════════════════════════════════

# ── VARIANT A: upload súborov ──
cp ~/poznamky/php/index-upload.php ./src/index.php

# ── VARIANT B: API logger ──
cp ~/poznamky/php/index-logger.php ./src/index.php

# ── VARIANT C: InitContainer + šablóna ──
cp ~/poznamky/php/index-template.php ./src/index.php
# DODATOČNE: v k8s/deployment.yaml ODKOMENTUJ riadky označené:
#   "ODKOMENTUJ pre VARIANT C"
# (volume cfg, mount cfg, cp príkaz v initContaineri)

# ── VARIANT D: Markdown CMS ──
cp ~/poznamky/php/index-cms.php ./src/index.php

# ── VARIANT A+C COMBO: Upload + InitContainer šablóna (najviac bodov) ──
cp ~/poznamky/php/index-upload-init.php ./src/index.php
cp ~/poznamky/k8s/deployment-upload-init.yaml ./k8s/deployment.yaml
# (toto deployment.yaml má InitContainer aktivovaný, netreba odkomentovať nič)

═══════════════════════════════════════
3. (BONUS) PRIDAJ PROBE ENDPOINTY
═══════════════════════════════════════

cp ~/poznamky/php/health.php ./src/
cp ~/poznamky/php/ready.php  ./src/
# v k8s/deployment.yaml odkomentuj sekciu readinessProbe + livenessProbe

═══════════════════════════════════════
4. BUILD IMAGE + LOAD DO MINIKUBE
═══════════════════════════════════════

docker build -t exam-app -f Dockerfile .
minikube image load exam-app:latest

═══════════════════════════════════════
5. NASADENIE
═══════════════════════════════════════

kubectl apply -f k8s/

# Over že všetko beží:
kubectl -n exam-test1 get all
kubectl -n exam-test1 get pvc

# Status musí byť:
#   pod          1/1   Running
#   pvc          Bound
#   service      NodePort
#   deployment   1/1

═══════════════════════════════════════
6. OTVOR APLIKÁCIU CEZ LOCALHOST
═══════════════════════════════════════

kubectl -n exam-test1 port-forward svc/exam-svc 8080:80 
kubectl -n exam-test1 port-forward svc/exam-svc <pozadovany port>:80 
Ako to čítať                                                                  
                                                                  
  kubectl port-forward svc/exam-svc  5331  :  80                                
                                     ↑       ↑                                  
                            tvoj localhost   port služby v klastri
                            (čokoľvek)       (musí sedieť so service.yaml) 

# v prehliadači:  http://localhost:8080
                  http://localhost:<pozadovany port>


  Príklad — predstav si že Apache by bežal na 8080

  # deployment.yaml
  containerPort: 8080      # Apache počúva tu

  # service.yaml
  port: 80                 # service vystupuje navonok na 80 (môže byť hocičo)
  targetPort: 8080         # MUSÍ byť 8080 — kam service pošle traffic

  kubectl port-forward svc/exam-svc 5331:80
  #                                      ↑ to je `port` zo service.yaml  
═══════════════════════════════════════
7. DÔKAZ PERZISTENCIE (povinný pri obhajobe!)
═══════════════════════════════════════

# 1. spravíš zmenu cez UI (upload, log, post)
# 2. zničíš pod:
kubectl -n exam-test1 delete pods --all

# 3. počkáš kým sa nový vytvorí (5-10s):
kubectl -n exam-test1 get pods

# 4. refreshneš prehliadač — dáta sú stále tam (PVC funguje)

═══════════════════════════════════════
8. PRÍKAZY KEĎ NIEČO NEFUNGUJE
═══════════════════════════════════════

# Logy aplikácie
kubectl -n exam-test1 logs deploy/exam-app

# Logy InitContainera
kubectl -n exam-test1 logs deploy/exam-app -c init-data

# Detail podu (status, events)
kubectl -n exam-test1 describe pod -l app=exam-app | tail -40

# Vstup do podu
kubectl -n exam-test1 exec -it deploy/exam-app -- bash

# Pozri obsah PVC z podu
kubectl -n exam-test1 exec deploy/exam-app -- ls -la /var/www/html/data

# Reštartuj pody (po zmene ConfigMap)
kubectl -n exam-test1 rollout restart deployment/exam-app

═══════════════════════════════════════
9. UPRATANIE
═══════════════════════════════════════

kubectl delete -f k8s/
kubectl delete pv exam-pv

═══════════════════════════════════════
NAJČASTEJŠIE CHYBY
═══════════════════════════════════════

unknown field "spec.HostPath"
  → camelCase: hostPath (malé h)

port already allocated
  → zmeň nodePort v service.yaml (rozsah 30000-32767)

ImagePullBackOff
  → zabudol si: minikube image load exam-app:latest

Permission denied (mkdir, write) v PHP
  → InitContainer nebeží alebo nerobí chown 33:33

Pending PVC
  → nesedí storageClassName medzi PV a PVC, alebo PV už zabraný

localhost:30080 neodpovedá
  → docker driver Minikube — použi:
     kubectl -n exam-test1 port-forward svc/exam-svc 8080:80
