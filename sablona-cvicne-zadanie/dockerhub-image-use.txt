================================================================================
  POUŽITIE IMAGE-U Z DOCKER HUBU V KUBERNETES DEPLOYMENTOCH
================================================================================

Áno, pre VEREJNÝ image stačí `username/image:tag` v spec.containers[].image:

    containers:
      - name: exam-be
        image: erikhorvath/exam-be:latest    # ← stačí toto

K8s pri štarte podu spraví `docker pull` z Docker Hubu (defaultný registry).


--------------------------------------------------------------------------------
  ALE POZOR NA 3 VECI
--------------------------------------------------------------------------------

1) VYHOĎ `imagePullPolicy: IfNotPresent`
----------------------------------------

    image: erikhorvath/exam-be:latest
    imagePullPolicy: IfNotPresent   # ← ZMAZAŤ alebo zmeniť na Always

`IfNotPresent` znamená "ak je local cache, použi cache, neťahaj".
Pri Docker Hub image-och chceš `Always` (pri :latest to k8s aj tak robí defaultne).

  +--------------+-------------------------------------------------------------+
  | Hodnota      | Význam                                                      |
  +--------------+-------------------------------------------------------------+
  | Always       | Vždy pull z registry. DEFAULT pre :latest                   |
  | IfNotPresent | Iba ak chýba locally. DEFAULT pre konkrétny tag (:1.2.3)    |
  | Never        | Nikdy nepull (len lokálne) — pri `minikube image load`      |
  +--------------+-------------------------------------------------------------+


2) `minikube image load` UŽ NEROB
---------------------------------

Tento krok bol potrebný len keď image existoval IBA lokálne v tvojom Dockeri
a nie v žiadnom registry. Keď je na Docker Hube, minikube si ho stiahne sám.

  # pôvodný workflow (lokálny image):
  docker build -t exam-be:latest .
  minikube image load exam-be:latest        # ← už netreba
  kubectl apply -f k8s/

  # nový workflow (Docker Hub):
  docker build -t erikhorvath/exam-be:latest .
  docker push erikhorvath/exam-be:latest    # ← najprv pushnúť!
  kubectl apply -f k8s/


3) PRE PRIVÁTNY REPO POTREBUJEŠ imagePullSecret
-----------------------------------------------

Verejný repo (default na Docker Hube) — funguje bez prihlásenia.
Privátny repo — musíš dať klastru credentials:

  kubectl create secret docker-registry dockerhub-cred \
    --docker-server=https://index.docker.io/v1/ \
    --docker-username=erikhorvath \
    --docker-password=dckr_pat_xxxxx \
    --docker-email=mail@example.com \
    -n exam-meno

A v deploymente:

  spec:
    template:
      spec:
        imagePullSecrets:
          - name: dockerhub-cred       # ← odkaz na vyššie vytvorený Secret
        containers:
          - name: exam-be
            image: erikhorvath/exam-be:latest


--------------------------------------------------------------------------------
  PRAKTICKÝ TIP: NEPOUŽÍVAJ :latest V PRODUKCII
--------------------------------------------------------------------------------

  image: erikhorvath/exam-be:latest        # ← rolling deploy zlyhá
                                           #    (k8s nevie že je nový)
  image: erikhorvath/exam-be:v1.2.3        # ← lepšie, immutable
  image: erikhorvath/exam-be:sha-abc1234   # ← najlepšie, git commit sha

Pri :latest keď spravíš `docker push`, K8s nevie že sa zmenil — pody si
nepullnu novú verziu, pokým ich nezabiješ. Konkrétny tag = jasná zmena
image-u → rolling update funguje.


--------------------------------------------------------------------------------
  TL;DR PRE CVIČNÚ ÚLOHU
--------------------------------------------------------------------------------

  # Pôvodne (lokálny image, minikube image load):
  image: exam-be:latest
  imagePullPolicy: IfNotPresent

  # S Docker Hubom:
  image: erikhorvath/exam-be:latest
  # (imagePullPolicy zmaž — pre :latest sa Always použije sám)

Plus `docker push erikhorvath/exam-be:latest` pred `kubectl apply`.
Žiadne `minikube image load`.
